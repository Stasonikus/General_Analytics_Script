1. ОБЩАЯ ЦЕЛЬ ПРОЕКТА
======================

Проект представляет собой набор Python-обработок для аналитики Excel-выгрузок по перевозкам, электронным пломбам/НП, конечным и стартовым точкам маршрутов, владельцам пломб и расчету коэффициента ротации пломб.

Основная идея проекта:
- входные Excel/CSV файлы кладутся в папку src/in;
- пользователь запускает нужную job через python -m src.main <job_name>;
- job читает входные файлы, выполняет фильтрацию/агрегацию/сравнение;
- результат записывается в Excel в папку src/out;
- ход работы пишется в консоль и в лог src/logs/app.log.

Скрипт развивался под практические задачи:
- сверка списка НП с выгрузкой перевозок;
- поиск пломб, которые есть в выгрузке, но отсутствуют в списке;
- аналитика Start waypoint / End waypoint;
- группировка адресов и таможенных постов в логические точки;
- помесячная аналитика оборота пломб;
- расчет коэффициента возврата/ротации электронных пломб по списку и выгрузке;
- фильтрация данных по конкретным спискам пломб, странам, статусам, владельцам и датам.

4. ГЛАВНЫЙ ЗАПУСК: src/main.py
=============================

Файл:
src/main.py

Назначение:
Главная точка входа проекта.

Что делает:
1. Читает имя job из аргументов командной строки.
2. Если имя не передано - выводит список доступных обработок.
3. Если передано list/help - выводит список job.
4. Ищет job в JOB_MODULES из src/core/config.py.
5. Динамически импортирует модуль job через importlib.
6. Проверяет наличие функции run().
7. Запускает job_module.run().
8. Логирует успех или ошибку.

Пример:

    python -m src.main job_point_analytics

Важно:
main.py не содержит бизнес-логики. Он только выбирает и запускает нужную обработку.


5. НАСТРОЙКИ: src/core/config.py
================================

Файл:
src/core/config.py

Назначение:
Центральный конфигурационный файл проекта.

Что содержит:
- BASE_DIR - корень src;
- IN_DIR - папка входных файлов;
- OUT_DIR - папка выходных отчетов;
- DATA_DIR - папка справочников;
- пути к JSON-справочникам локаций;
- настройки движков Excel;
- DEFAULT_JOB;
- JOB_MODULES - реестр всех job.

JOB_MODULES:
Это словарь, где ключ - имя job для запуска, а значение - путь к Python-модулю.

Пример записи:

    "job_point_analytics": {
        "module": "src.jobs.job_point_analytics",
        "description": "Аналитика пломб по конечным точкам с группировкой адресов по областям/городам",
    }

Важно:
Если job есть в папке src/jobs, но не добавлена в JOB_MODULES, через main.py она не запустится.

Замечание:
В реестре есть исторические job, для которых файлов сейчас может не быть:
- job_seals_structure;
- 1Stage;
- 12ATStageTest.
Такие записи являются заготовками/остатками старой архитектуры и при запуске дадут ошибку импорта, если соответствующий файл отсутствует.

11. JOB: jobPROVERCA_NP.py
=========================

Команда:

    python -m src.main jobPROVERCA_NP

Назначение:
Сравнение списка НП/пломб с выгрузкой перевозок.

Листы:
- Статистика;
- Не найдены;
- Найдены;
- Детали совпадений.

Цель:
Быстро проверить, какие НП из отдельного списка реально присутствуют в системной выгрузке, сколько раз встречаются и куда направлены.

13. JOB: job_point_analytics.py
===============================

Файл:
src/jobs/job_point_analytics.py

Команда:

    python -m src.main job_point_analytics

Можно сразу выбрать режим:

    python -m src.main job_point_analytics 1
    python -m src.main job_point_analytics 2

Режимы:
- 1 - Start waypoint: откуда уезжают пломбы;
- 2 - End waypoint: куда приезжают пломбы.

Назначение:
Аналитика количества пломб по стартовым или конечным точкам маршрута.

Вход:
- Выгрузка*.xlsx/.xls/.csv.

Ключевые колонки:
- План установки пломб;
- Start waypoint;
- End waypoint;
- Status date.

Особенности:
1. Поддерживает несколько колонок пломб:
   - План установки пломб;
   - План установки пломб.1;
   - План установки пломб.2;
   - и так далее.
2. Корректно обрабатывает числа вида 10915.0 как одну пломбу, а не как 10915 и 0.
3. Группирует адреса в логические точки.
4. Таможенные посты Т/П оставляет самостоятельными точками.
5. Казахстан, Алматы и Казахстан, Алматинская область объединяются в одну группу:
   "Казахстан, Алматы и Алматинская область".
6. Строит помесячную аналитику по Status date без учета дня, только по месяцу:
   2026-02, 2026-03, 2026-04 и т.д.

Выход:
Для режима 1:
    report_start_points_<дата_время>.xlsx

Для режима 2:
    report_end_points_<дата_время>.xlsx

Листы:
- Аналитика точек;
- Детали точек;
- Оборот по месяцам.

Лист "Аналитика точек":
Показывает точку, количество пломб и количество разных исходных адресов.

Лист "Детали точек":
Показывает исходные строки, номера пломб, дату Status date, месяц и группу точки.

Лист "Оборот по месяцам":
Показывает количество пломб по каждой точке в разрезе месяцев.

Цель:
Понять, откуда и куда чаще всего движутся пломбы, а также распределить оборот пломб по месяцам.


14. JOB: job_seal_rotation.py
=============================

Файл:
src/jobs/job_seal_rotation.py

Команда:

    python -m src.main job_seal_rotation

Если обычный python без pandas:

    C:\Users\admin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe -m src.main job_seal_rotation

Назначение:
Расчет коэффициента ротации/возврата электронных пломб.

Вход:
- обязательный файл Выгрузка*.xlsx/.xls/.csv;
- необязательный файл Список.xlsx.

Если Список.xlsx есть:
    job использует только пломбы из этого списка.

Если Список.xlsx отсутствует:
    программа спрашивает:
    "Продолжить без фильтрации пломб? (Y/N)"

Ключевые колонки выгрузки:
- Дата;
- Status date;
- План установки пломб.

Что делает:
1. Читает выгрузку.
2. Читает Список.xlsx, если он есть.
3. Извлекает все пломбы из "План установки пломб".
4. Если есть список, оставляет только пломбы из списка.
5. Каждую пломбу превращает в отдельную запись.
6. Для каждой уникальной пломбы берет первое появление по дате начала.
7. Считает время перевозки:

       Дней в перевозке = Status date - Дата

8. Считает:
   - среднее время перевозки;
   - минимальное время перевозки;
   - максимальное время перевозки.
9. Дополнительно ищет повторные появления одной и той же пломбы и строит интервалы возврата:

       Дней возврата = начало следующей перевозки - конец предыдущей перевозки

   Эти интервалы сохраняются на отдельный лист как справочная аналитика.
10. При запуске спрашивает направление возврата для коэффициента:
    - 1 - РФ, 10 дней;
    - 2 - Беларусь, 10 дней;
    - 3 - Кыргызстан, 3 дня.
11. Считает коэффициент ротации:

       Коэффициент ротации =
       (Среднее время перевозки, дней + Договорной срок, дней + Дней возврата для коэффициента) / 30

    Договорной срок сейчас равен 20 дням.

Выход:
Excel-файл:
    Коэффициент_возврата_пломб_<дата_время>.xlsx

Листы:
- Сводка;
- Уникальные пломбы;
- Возвраты пломб.

Лист "Сводка":
Показывает:
- файл выгрузки;
- наличие фильтра Список.xlsx;
- количество записей пломб после фильтрации;
- количество уникальных пломб;
- количество найденных интервалов возврата;
- среднее/минимальное/максимальное время перевозки;
- выбранное направление возврата;
- дни возврата для коэффициента;
- договорной срок;
- полный цикл пломбы;
- коэффициент ротации;
- формулу расчета.

Лист "Уникальные пломбы":
Содержит только первую перевозку каждой пломбы:
- Пломба;
- Дата начала;
- Дата окончания;
- Дней в перевозке.

Лист "Возвраты пломб":
Содержит найденные интервалы между повторными перевозками одной и той же пломбы:
- Пломба;
- Конец предыдущей перевозки;
- Начало следующей перевозки;
- Дней возврата.

Цель:
Оценить, насколько быстро пломбы проходят цикл "уехала - была в перевозке - вернулась/готова к следующему рейсу", и получить коэффициент ротации для планирования потребности в пломбах.

4. Удаляет строки, где страна назначения - Республика Казахстан.
5. Удаляет дубли по Номер ТС.
6. Оставляет строки только с разрешенными кодами товара.

Выход:
Excel-файл result_job1_<дата>.xlsx.

Листы:
- лист1 - подготовленные данные;
- лист2 - после удаления Казахстана;
- лист3 - после удаления дублей;
- лист4 - финальный результат.

Цель:
Получить очищенную выборку перевозок по нужным товарным кодам без Казахстана и дублей по ТС.

28. РЕКОМЕНДАЦИИ ПО РАЗВИТИЮ ПРОЕКТА
====================================

1. Новые job писать по актуальному шаблону:
   - импортировать OUT_DIR/IN_DIR из src.core.config;
   - читать Excel через src.io.io_excel;
   - логировать через src.core.logger;
   - защищать выходные DataFrame через protect_from_excel_formulas.

2. Для всех новых job обязательно:
   - функция run();
   - запись в JOB_MODULES;
   - понятная маска входных файлов;
   - проверка обязательных колонок;
   - логирование количества строк до/после фильтрации;
   - выходной Excel с датой/временем в имени.

3. Старые job желательно мигрировать:
   - job2.py;
   - job3.py;
   - job_example.py;
   - job_template.py;
   - job_utils.py.

4. Служебные __pycache__ и временные Excel-файлы лучше не хранить в git.

5. Для аналитики по пломбам важно всегда учитывать:
   - в одной ячейке может быть несколько номеров;
   - Excel может прочитать номер как 12345.0;
   - пломба может повторяться в выгрузке несколько раз;
   - повтор пломбы означает новый цикл использования;
   - при расчете уникальных пломб нужно явно выбирать: считать первое появление или все циклы.


29. КРАТКАЯ КАРТА АКТУАЛЬНЫХ JOB
================================

jobPROVERCA_NP
    Сравнить список НП с выгрузкой и показать найденные/ненайденные.

jobPROVERCA_NP_SORT_BY_DATE
    Найти НП, которые есть в выгрузке, но отсутствуют в списке.

job_point_analytics
    Посчитать пломбы по Start waypoint или End waypoint, сгруппировать точки и показать оборот по месяцам.

job_seal_rotation
    Рассчитать коэффициент ротации пломб по среднему времени перевозки, договорному сроку и выбранной стране возврата.

jobRF_IN_OUT
    Посчитать потоки РФ -> КЗ по заданным таможенным постам.

job1
    Очистить и отфильтровать ТО отправления по стране, ТС и товарным кодам.

job2/job3
    Исторические обработки по распределению НП по владельцам.


30. ГЛАВНАЯ БИЗНЕС-ЦЕЛЬ СКРИПТА
===============================

Главная цель проекта - быстро превращать сырые Excel-выгрузки перевозок в управленческую аналитику по пломбам:

- сколько пломб участвует в перевозках;
- какие пломбы есть/нет в контрольных списках;
- куда пломбы приезжают и откуда уезжают;
- как меняется оборот пломб по месяцам;
- сколько времени пломба находится в пути;
- какой коэффициент ротации нужен для планирования количества пломб;
- какие направления и точки дают основную нагрузку.

Проект ориентирован не на разовый отчет, а на повторяемый рабочий процесс:
положил новую выгрузку в src/in -> запустил нужную job -> получил Excel-отчет в src/out.
